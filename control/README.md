# Control：动作执行与稳定等待

本目录把 VISTA 提交的动作转换为底盘、机械臂和夹爪指令，并判断动作何时可以返回。控制代码通过根目录 `hal.py` 的接口访问机器人，MuJoCo 实现在 `sim/backend.py`；看图规划和纠错由 VISTA 完成。

**稳定等待用于 VISTA 动作原语。** ACT rollout 直接向同一个后端发送五维执行器目标，每拍执行 0.1 秒，不调用这些原语或稳定等待；两者共用后端的物理与抓取规则。

## 配置与运行

环境安装和模型端点配置见[主 README](../README.md#环境安装)。`control` 没有独立启动入口，由采集器调用；以下命令在项目根目录运行：

```bash
export MUJOCO_GL=egl
python -u run_collect.py \
  --brain vista --episodes 1 --seed 0 --max-decisions 64 \
  --out data/episodes --brain-memory output/vista --dataset-out data/act_v1
```

再次采集时使用新的 seed。控制频率、动作速度、臂预设和稳定阈值集中在根目录 `config.py`。

## 动作如何执行

```text
VISTA decide() → play(actions)
  → run_collect.py 按顺序执行
  → ToolLayer → BaseDriver / ArmDriver → HAL → MuJoCo
  → 每拍记录数据、更新观测
  → accept_batch_result(执行回执, 连续观测窗口)
  → 下一次 decide()
```

VISTA 的 `play` 可提交十种动作，完整参数见 [VISTA README](../brains/vista/README.md#执行与结束)。

| 动作 | 控制方式 |
| --- | --- |
| `forward` / `back` | 以 ±0.3 m/s 的目标速度执行指定时长，然后停止底盘并等待稳定 |
| `turn_left` / `turn_right` | 用初始目标角速度 1 rad/s × 指定秒数确定目标转角；根据底盘转角减速，到目标的 95% 即停止，另设步数上限 |
| `arm_pose` | 移到 `stow / reach / carry / drop` 预设；每拍每个关节目标最多变化 0.3 rad，最后下发精确目标 |
| `shoulder` / `elbow` | 相对当前实测关节角微调，单次增量限制为 ±0.5 rad，沿用机械臂移动流程 |
| `open_gripper` / `close_gripper` | 下发开闭目标，分别检查实际开度或后端的稳定夹持确认；闭爪先停止底盘 |
| `observe` | 停止底盘、保持臂爪目标，推进至少一拍，取得新观测 |

`finish` 由外层接收，记为 `done` 并返回接受回执，不执行运动，也不证明任务成功。

## Stability：什么算稳定

`stability.py` 比较**相邻两个 10 Hz 控制边界**的 RGB 图像和实测状态。以下条件必须同时满足：

| 检查 | 当前规则 |
| --- | --- |
| 图像变化 | 先逐像素计算 RGB 绝对差，再按 3×3 像素分块；任一通道的块内平均差 > 5，就记为变化块 |
| 全局图像 | 未变化块比例 ≥ 99.8% |
| 局部图像 | 重叠的 24×24 像素窗口中，变化块比例均 ≤ 10%；防止小球运动被大面积静止背景掩盖 |
| 状态变化 | 肩角、肘角、夹爪开度、底盘线速度、角速度的相邻帧差分别 ≤ `0.001 rad、0.001 rad、0.002、0.002 m/s、0.005 rad/s` |
| 底盘停止 | 当前速度绝对值还须 ≤ `0.002 m/s、0.005 rad/s`，避免把匀速运动误判为停止 |

先取绝对差再分块，避免同一块内正负像素变化相互抵消。目前一个相邻帧对满足条件即可判稳，没有额外的多帧持续稳定窗口。这个判定表示观测近似静止，**不能单独证明关节到位、抓住球或任务完成**。

## 怎样减少重复等待

`wait_until_stable()` 将固定等待改为有上限的逐拍检查：每推进一拍，读取采集器已经更新的观测；满足稳定条件和动作自己的完成条件，就提前返回。它不额外调用相机，不用反复读取同一帧代替新观测。

| 等待位置 | 时间上限 | 提前结束还须满足 |
| --- | --- | --- |
| 底盘动作后的停止等待 | 0.2 秒 | 观测稳定 |
| 机械臂移到目标后的等待 | 0.3 秒 | 观测稳定，且实测肩肘角与目标的误差范数 ≤ 0.03 rad |
| 张爪 | 0.8 秒 | 观测稳定，且归一化开度距目标 ≤ 0.02 |
| 闭爪 | 1.2 秒 | 观测稳定，且后端已确认夹持 |
| `observe` | 默认 0.1 秒，可指定至 3 秒 | 观测稳定 |

时间均为仿真时间；等待上限按 0.1 秒向下取整，每次至少执行一拍。例如机器人已张开且稳定，再次张爪通常只需 0.1 秒，不必等满 0.8 秒。重复动作仍会执行，不做去重；机械臂仍下发最终目标，小幅微调不会因容差而被丢弃。

达到时间上限只表示等待结束，动作随后单独检查结果：机械臂最终角度误差范数 > 0.35 rad 才报告失败；张爪未到目标报告失败；闭爪未确认夹持返回 `GRASP_NOT_CONFIRMED`。因此，“提前结束的严格条件”和“最终失败条件”并不相同。闭爪等待结束后，闭合目标仍保持施加。

前后移动的指定运动时长不会被稳定判定截短。一次 `play` 的动作依次执行，批次末尾不再额外叠加一轮固定等待；正常 episode 结束后的 **3 秒收尾仿真仍保留**。独立调用驱动而未提供观测读取器时，会执行完整等待上限。

后端的“稳定夹持”也与这里的“观测稳定”不同：前者由 `sim/backend.py` 检查球与两侧指垫的有效接触、开度及持续时间，确认窗口为 0.1 秒；后者只比较图像与机器人状态。闭爪要提前返回，两者都要满足。

## VISTA harness 能收到什么

外层采集器把**结构化执行回执和连续观测窗口**交给 `VistaBrain.accept_batch_result()`。Harness 归档批次内每个控制边界的观测，再向模型发送回执、批次最终图及同一时刻的状态；中间帧可通过 `history / inspect / read_pixels` 查询。

| 信息 | 模型看到的内容 |
| --- | --- |
| 视觉 | 320×240 车头 RGB；帧号、图片尺寸、归档路径和所属批次等元信息 |
| 实测状态 | `shoulder_rad`、`elbow_rad`、`gripper_opening`、`base_v_mps`、`base_w_radps`；夹爪开度是 `[0,1]` 连续值 |
| 批次回执 | 批次和工具调用 ID、起止帧、整批执行状态 |
| 每个动作 | 名称与参数、帧区间、`completed / failed / unknown / not_executed` 状态，以及 `action_applied`（已施加、未施加或未知） |
| 错误反馈 | 经过筛选的错误码、说明和是否可重试；闭爪未确认时明确返回 `GRASP_NOT_CONFIRMED` |

**闭爪成功回执包含后端已确认夹持这一事实**，但不提供被夹物体的名字或坐标；模型仍需看图确认抬臂后的离地与持球关系。其他动作的 `completed` 只表示控制调用完成，不等于任务成功。

原始驱动文本可能包含底盘位姿等内部诊断，只进入外层日志，不原样发给模型。球、箱子的真值坐标、完整仿真 `qpos/qvel`、稳定比较分数也不自动进入模型消息。`perception.py` 的检测结果没有接入当前 VISTA 或 ACT 主流程。

已知动作失败通常停止本批后续动作，模型收到新图后再决定。连续两次闭爪有一项明确例外：第一次未确认夹持时，仍可执行紧邻的第二次闭爪；第二次失败则停止后续动作。执行进度未知或无法取得可靠观测时终止采集，避免重放效果不明的动作。

## 文件布局

```text
control/
├── README.md       # 控制调用、稳定判定、等待优化和 VISTA 信息边界
├── __init__.py     # 导出驱动、运动学、工具层和 perception
├── tools.py        # 注册动作、参数说明与执行分发；实现 observe
├── drivers.py      # 底盘运动、臂姿态与微调、开闭爪、完成和失败条件
├── stability.py    # 图像/状态比较，以及有上限的提前结束等待
├── kinematics.py   # 两关节平面臂正逆运动学、几何与关节限制
└── perception.py   # 颜色分割、连通域、方位与投影测距；保留但主流程未调用
```

相关模块：根目录 `config.py` 提供控制常量，`hal.py` 定义接口，`observations.py` 定义同步观测；`sim/backend.py` 实现物理执行与抓取确认，`sim/env.py` 管理观测流和任务判定，`run_collect.py` 连接控制、记录器和 VISTA。模型侧协议与工具说明见 [VISTA README](../brains/vista/README.md)，策略部署见 [ACT README](../act/README.md)。
